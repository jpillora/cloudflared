# FORK.md — jpillora/cloudflared (embed fork)

This is a fork of [`cloudflare/cloudflared`](https://github.com/cloudflare/cloudflared) that adds
a small, additive **in-process embedding API** so a host Go application can run a Cloudflare
Tunnel as a library — like Tailscale's `tsnet` — instead of shelling out to the `cloudflared`
binary.

It was created for [rais](https://github.com/jpillora/rais)'s "one-click public URL" feature
(the public sibling of rais's embedded Tailscale integration). No subprocess, no binary to
install/detect/supervise, and the quick-tunnel URL is known programmatically instead of by
scraping logs.

- **Upstream:** `cloudflare/cloudflared` (remote `upstream`)
- **Fork:** `jpillora/cloudflared` (remote `origin`)
- **Patch branch:** `embed`
- **Module path: RENAMED** — `module github.com/jpillora/cloudflared`, with every internal
  `github.com/cloudflare/cloudflared/...` import rewritten to `github.com/jpillora/cloudflared/...`.
  This lets a host import the fork directly (`import "github.com/jpillora/cloudflared/..."` +
  `require github.com/jpillora/cloudflared`) with **no `replace` aimed at the cloudflare namespace**.
  A Go module is consumable under exactly one import path, so the only way to import it *as*
  `jpillora` is for its own code to import itself *as* `jpillora`. The rewrite is mechanical and
  regenerable via `scripts/rename-fork.sh`; the upstream-tracking `master` branch keeps the original
  cloudflare paths, so re-syncing stays "merge upstream, then re-run the script" (see "Re-syncing").

## Design goals

1. **Tiny hand-maintained diff.** The only *hand-written* divergence from upstream is **7 files**
   (`cmd/cloudflared/tunnel/embed.go` + `ingress/memory_origin.go` new; `cmd/cloudflared/tunnel/cmd.go`
   + `connection/observer.go` + `ingress/origin_service.go` + `orchestration/config.go` +
   `orchestration/orchestrator.go` edited), so re-syncing the logic stays cheap. The jpillora namespace
   rename spans ~182 files but is 100% mechanical — regenerated by `scripts/rename-fork.sh`, never
   hand-edited (see "Re-syncing").
2. **Host owns process lifecycle.** Embedded, cloudflared must not trap OS signals, init sentry,
   notify systemd, run its autoupdater, or bind a metrics port (opt-in via `MetricsAddr`). Shutdown
   is entirely `context.Context`-driven.
3. **Observable without log scraping.** Status (URL, connected, disconnected) is delivered through
   cloudflared's existing `connection.Observer` event sink.
4. **Multi-instance safe.** Any number of `Tunnel` instances may `Run`/`Listen` concurrently in one
   process. cloudflared's per-tunnel metric registration is redirected off the host's default
   prometheus registry (so it neither collides nor registers anything automatically — metrics are
   opt-in via `MetricsAddr`), and the event-sink dispatch race that dropped quick-tunnel URLs under
   concurrency is fixed.

## What changed vs upstream

### 1. `cmd/cloudflared/tunnel/embed.go` (new file)

The public entrypoint, in `package tunnel` so it can reach the package's unexported helpers
(`tunnelFlags`, `buildRunCommand`, `ParseToken`, `StartServer`, `Init`, `httpTimeout`,
`QuickTunnelResponse`).

The API is **instance-based** and **Listen-only** — no package-level/global entrypoints, and the
host always serves an in-process `http.Handler` (there is no TCP-origin proxying mode). Create a
`Tunnel` with options, then `Listen`; shutdown is entirely `ctx`-driven (cancel the context passed
to `Listen`, or close the listener).

```go
// Config configures an in-process cloudflared Tunnel — the programmatic
// equivalent of the flags a `cloudflared tunnel run` invocation would parse.
type Config struct {
    Token           string                   // named tunnel token; empty => account-less quick tunnel
    QuickServiceURL string                   // default "https://api.trycloudflare.com"
    Logger          *zerolog.Logger          // required
    Sink            connection.EventSinkFunc // receives SetURL / Connected / Disconnected / ... events
    Version         string                   // reported in User-Agent + build info
    MetricsAddr     string                   // opt-in: run metrics/diagnostics here; empty => no OS TCP listener
    LocalOrigin     bool                     // named tunnels: keep this host's Listen handler as the origin, ignoring dashboard-managed config
}

// Tunnel is a single in-process cloudflared tunnel. One-shot: use a fresh
// instance per run.
type Tunnel struct { /* unexported */ }

func New(c Config) *Tunnel                                          // tunnel configured with c
func (t *Tunnel) Listen(ctx context.Context) (net.Listener, error) // returns a listener; tunnel connects in background

// ClientIPMiddleware rewrites r.RemoteAddr from Cloudflare's Cf-Connecting-Ip
// header (the real client IP) — a handler served over a Listen listener
// otherwise sees the in-memory origin conn's meaningless RemoteAddr. The Cloudflare
// analog of tailscale's WhoIsMiddleware.
func ClientIPMiddleware(next http.Handler) http.Handler
```

Usage: `ln, _ := tunnel.New(tunnel.Config{...}).Listen(ctx)`, then
`http.Serve(ln, tunnel.ClientIPMiddleware(h))`. `Listen` owns a private in-memory origin, so no OS
TCP port is bound and the listener *is* the tunnel.

What it does:
- Calls `makeMultiInstanceSafe(info)` (once per process, via `sync.Once`, embedded path only) to:
  - `Init(info, make(chan struct{}))` — populate cloudflared's package globals `buildInfo` and
    `graceShutdownC` (normally set by the CLI entrypoint). **Required** — without it `StartServer`
    nil-derefs at the diagnostic collector (`cmd.go`, `buildInfo.CloudflaredVersion`). The `Once`
    also removes the data race concurrent `Run`/`Listen` calls would otherwise have on these globals.
  - Redirect `prometheus.DefaultRegisterer`/`DefaultGatherer` to a **private, duplicate-tolerant
    registry**. cloudflared hardcodes metric registration onto the process-global default registry
    *per tunnel* (e.g. `supervisor.NewSupervisor` → `v3.NewMetrics`), which without this both
    pollutes the host's default registry as a side effect of embedding *and* panics on the second
    concurrent tunnel (`duplicate metrics collector registration attempted`). After the swap nothing
    lands on the host's real default registry, concurrent tunnels don't panic, and the opt-in
    metrics server (`MetricsAddr`) still serves cloudflared's metrics (`promhttp.Handler()` reads
    `DefaultGatherer`). With `MetricsAddr` empty (default) no metrics are registered or exposed —
    metrics are never automatic.
- Builds a `*cli.Context` by `.Apply`-ing cloudflared's own `tunnelFlags(false)` +
  `buildRunCommand().Flags` onto a `flag.FlagSet` (so **all upstream flag defaults are preserved**),
  then overrides only `unix-socket` (Listen's private origin), `protocol=quic`, `ha-connections=1`,
  `no-autoupdate=true`, `quick-service`, and (named) `token`. Sets `c.Context = ctx`.
- **Quick mode** (`Token == ""`): POSTs `"<QuickServiceURL>/tunnel"` (mirroring upstream
  `RunQuickTunnel`), reads `QuickTunnelResponse`; the public hostname is `Result.Hostname`
  (known synchronously) and the credentials come from the same response. Then calls
  `StartServer(..., &connection.TunnelProperties{Credentials, QuickTunnelUrl}, ..., withEmbedded(sink))`.
- **Named mode** (`Token != ""`): `ParseToken(Token)` → `StartServer(..., &connection.TunnelProperties{Credentials: tok.Credentials()}, ..., withEmbedded(sink))`.
  The public hostname is **not** in the token (it's whatever the user routed in the Cloudflare
  dashboard), so the host supplies it separately for display.

`Tunnel.Listen` drives all of this: it creates a private **in-memory** origin
(a `bufconn` listener — no filesystem, no OS socket), points cloudflared at it via `--unix-socket`
whose value is a per-tunnel registry key (`cfembed-mem:<uuid>`) that `ingress.newHTTPTransport` dials
in memory, runs the tunnel in a goroutine, and returns the in-memory `net.Listener`.
`http.Serve(ln, tunnel.ClientIPMiddleware(handler))` then serves straight off the tunnel with **no OS
TCP port and nothing on disk**; closing the listener (or canceling ctx) tears the tunnel down and
unregisters the origin. `ClientIPMiddleware` restores the real client IP into `r.RemoteAddr` from the
`Cf-Connecting-Ip` header (otherwise the handler sees the in-memory conn's meaningless address).

It also defines the option plumbing consumed by the `StartServer` guards:

```go
type EmbedServerOption func(*embedServerOptions)
type embedServerOptions struct {
    embedded    bool
    sink        connection.EventSinkFunc
    metricsAddr string
    onConfig    func(func() ([]byte, error)) // receives the orchestrator's live config getter (GetMetadata)
    localOrigin bool                         // Config.LocalOrigin — ignore edge-pushed config
}
func withEmbedded(sink connection.EventSinkFunc, metricsAddr string, onConfig func(func() ([]byte, error)), localOrigin bool) EmbedServerOption
```

### 2. `cmd/cloudflared/tunnel/cmd.go` — `StartServer` guards (edited)

`StartServer` gained a trailing variadic parameter (existing CLI callers in `quick_tunnel.go` and
`subcommand_context.go` are unaffected — variadic is optional):

```go
func StartServer(
    c *cli.Context,
    info *cliutil.BuildInfo,
    namedTunnel *connection.TunnelProperties,
    log *zerolog.Logger,
    embedOpts ...EmbedServerOption, // NEW
) error {
    var emb embedServerOptions
    for _, opt := range embedOpts { opt(&emb) }
    ...
}
```

When `emb.embedded` is set, these are skipped (host owns the process):
- `sentry.Init(...)`
- `go waitForSignal(graceShutdownC, log)` — the OS SIGTERM/SIGINT trap
- `go notifySystemd(connectedSignal)`
- the `updater.NewAutoUpdater(...).Run(ctx)` goroutine (and its `wg.Add(1)`)
- the metrics/readiness/diagnostic HTTP server (`metrics.CreateMetricsListener` + `ServeMetrics`) —
  it binds an OS TCP listener, so embedded it is **opt-in** via `Config.MetricsAddr`. Empty
  (default) => no metrics server, no TCP listener. The guard is `if !emb.embedded || emb.metricsAddr != ""`.

And when a sink is provided, it is registered right after the observer is created:
```go
observer := connection.NewObserver(log, logTransport)
if emb.sink != nil { observer.RegisterSink(emb.sink) }
```

Everything else in `StartServer` is unchanged.

### 3. `connection/observer.go` — sink-dispatch ordering fix (edited)

`Observer.dispatchEvents` `select`s over two buffered channels: `addSinkChan` (sink registrations)
and `tunnelEventChan` (events). `StartServer` registers the embed sink and then, on the next line,
calls `observer.SendURL(quickTunnelURL)` for the quick-tunnel hostname — so the sink and the
`SetURL` event land in their respective buffers back-to-back. A bare `select` then picks between the
two channels **at random**, dispatching `SetURL` to an empty sink list roughly half the time and
silently dropping the tunnel URL. This is benign for the CLI (it registers its only sink much later
and reads the URL from logs) but breaks embedded quick tunnels — and gets far worse under
concurrency, where the scheduler routinely lets both sends buffer before the dispatch goroutine
runs. The fix drains any already-queued sink registrations before dispatching each event, so a sink
registered immediately before an event reliably receives it. Deterministic (the sink is buffered
before the event) and harmless to the CLI.

### 4. `orchestration/{config,orchestrator}.go` — local-origin override (edited)

A named tunnel's ingress is normally **owned by the Cloudflare dashboard**: on connect, the edge
pushes the tunnel's configuration (`hostname → service`) via the `UpdateConfiguration` RPC, which
the orchestrator applies — *overriding* the local `--unix-socket` origin the embed set up. For an
embedding host that wants to serve its own `Listen` handler (e.g. rais reverse-proxying to a dev
machine), that dashboard `service` URL is exactly what must be ignored.

`Config.LocalOrigin` (embed) → `orchestration.Config.IgnoreRemoteConfig` → a one-line gate at the
top of `Orchestrator.UpdateConfig`:

```go
// orchestration/config.go
type Config struct {
    ...
    IgnoreRemoteConfig bool // drop edge-pushed config; keep the local (startup) ingress in force
}

// orchestration/orchestrator.go — UpdateConfig, before the version check:
if o.ignoreRemote {
    // An embedding host that owns the origin keeps its local config in force.
    return &pogs.UpdateConfigurationResponse{LastAppliedVersion: o.currentVersion}
}
```

`currentVersion` starts at `-1` and never advances, so every remote push is acknowledged (the edge
sees `LastAppliedVersion` and stops retrying) but **never applied** — the startup ingress
(the in-memory origin behind `Listen`) stays in force, and every request for the tunnel's hostname
is served by the local handler regardless of the dashboard's routes. No effect on quick tunnels
(they have no remote config). Wired through `cmd.go`: `if emb.localOrigin { orchestratorConfig.IgnoreRemoteConfig = true }`
before `NewOrchestrator`. Verified end-to-end against a dashboard-routed named tunnel: with
`LocalOrigin:true` the local marker handler answered the public hostname instead of the dashboard's
(otherwise-502) service URL.

Dropping the push would also hide the tunnel's routes from `GetMetadata` (they only arrive in that
push). So the gate *retains* the ignored ingress (`reportedIngress`/`reportedVersion`) without
applying it, and `Orchestrator.GetReportedConfigJSON` — which the embed hands to `onConfig` instead
of `GetVersionedConfigJSON` — reports those hostnames for **display** while the local origin keeps
serving. A host can thus show "this tunnel routes `x.example.com` → my handler" even under override.

### 5. `embed/examples/fileserver/main.go` (new)

A ~40-line `main` that serves a directory over a quick tunnel with **no TCP port bound**:

```go
ln, _ := tunnel.New(tunnel.Config{Logger: &log, Sink: sink, Version: "fileserver-example"}).Listen(ctx)
defer ln.Close()
http.Serve(ln, tunnel.ClientIPMiddleware(http.FileServer(http.Dir(dir)))) // ln is the tunnel
```

Run `go run ./embed/examples/fileserver [dir]`, then open the printed
`https://<random>.trycloudflare.com` URL. Verified on the dev box: the handler serves over the
in-memory origin, the tunnel registers at the edge, `r.RemoteAddr` is the real client IP (via
`ClientIPMiddleware`), and the process opens **zero** TCP listeners (`ss -lntp` shows none; metrics
stay off unless `MetricsAddr` is set).

## Status events

The sink is a `connection.EventSinkFunc` receiving `connection.Event`. Relevant `EventType`s:
- `connection.SetURL` — `event.URL` holds the tunnel hostname (quick mode; fired as soon as the
  tunnel is allocated, before the edge connection is up). Note: bare hostname, prepend `https://`.
- `connection.Connected` — an edge connection registered (`event.Index`, `event.Location`).
- `connection.Disconnected` — an edge connection dropped.

This is how a host surfaces live tunnel status without parsing logs.

## Lifecycle & shutdown

- `Tunnel.Listen` returns immediately and runs the tunnel in the background until `ctx` is canceled
  or a fatal error occurs (which closes the returned listener).
- Cancel the `ctx` you passed in (or close the listener) to stop the tunnel. `StartServer` derives its server context from
  `c.Context`; canceling it stops the supervisor, which returns through the internal `errC`, and
  `waitToShutdown` unblocks on that. (The graceful `graceShutdownC` path is unused when embedded —
  we hand `Init` a fresh channel that is never closed.)
- No host signals are intercepted, so the host's own SIGTERM handling is unaffected.

## Consuming this fork (host `go.mod`)

The host imports `github.com/jpillora/cloudflared/cmd/cloudflared/tunnel` directly and requires
this fork. Because the fork owns the `jpillora` namespace end-to-end, **no `replace` aimed at the
cloudflare namespace is needed** — but the fork's own *dependency* replaces still must be mirrored:

```gomod
require github.com/jpillora/cloudflared v0.0.0-<ts>-<sha>   // or a tagged release
// For local dev instead: replace github.com/jpillora/cloudflared => ../cloudflared

// MIRROR cloudflared's own replace directives. Go does NOT apply a dependency's
// replaces to the main build, so without these the host pulls incompatible real
// quic-go / stock urfave-cli and fails to compile.
replace github.com/urfave/cli/v2           => github.com/ipostelnik/cli/v2 v2.3.1-0.20210324024421-b6ea8234fe3d
replace github.com/prometheus/golang_client => github.com/prometheus/golang_client v1.12.1
replace gopkg.in/yaml.v3                    => gopkg.in/yaml.v3 v3.0.1
replace github.com/quic-go/quic-go         => github.com/chungthuang/quic-go v0.45.1-0.20260529212404-a9fddf436fc4
```

(Those four are copied verbatim from this fork's `go.mod`; if upstream changes them, re-copy. They
are unavoidable regardless of the fork's module name — a dependency's own `replace` directives never
apply to the consumer's main build. The old `replace github.com/cloudflare/cloudflared => …` line is
**no longer needed**: consumers now require and import the `jpillora` module directly.)

Requirements: **Go 1.26+** (this module is `go 1.26`). cloudflared and quic-go are pure Go — no
CGO is added by embedding.

Minimal host usage (imports `github.com/jpillora/cloudflared/cmd/cloudflared/tunnel` and
`github.com/jpillora/cloudflared/connection`):

```go
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

logger := zerolog.New(io.Discard) // or bridge to your logger; status comes from the sink
sink := connection.EventSinkFunc(func(e connection.Event) {
    switch e.EventType {
    case connection.SetURL:       // e.URL -> "https://" + e.URL
    case connection.Connected:    // tunnel is live
    case connection.Disconnected: // dropped
    }
})

ln, err := tunnel.New(tunnel.Config{
    // Token: "<base64 CF tunnel token>", // omit for a quick tunnel
    Logger:  &logger,
    Sink:    sink,
    Version: "myapp",
}).Listen(ctx)
if err != nil { /* ... */ }
defer ln.Close()

// ln is backed by the Cloudflare edge, not an OS TCP port. Serve any handler;
// ClientIPMiddleware restores the real client IP into r.RemoteAddr.
http.Serve(ln, tunnel.ClientIPMiddleware(myHandler))
```

## Validation

Proven end-to-end with a standalone module (`/tmp/cfembed-smoke` on the dev box: a `go.mod` with
the replace set above + a ~40-line `main.go`). It:
1. started a local HTTP origin,
2. ran a `Tunnel` in quick mode,
3. received `SetURL` (`<random>.trycloudflare.com`) then `Connected` (edge `cbr01`),
4. fetched `https://<random>.trycloudflare.com` → **200**, body proxied from the local origin,
5. canceled the context → clean shutdown, `Run` returned `nil`, `Disconnected` fired.

The standalone binary was ~36 MB (a marker for the dependency weight embedding adds).

## Re-syncing with upstream

`master` tracks upstream **on the original cloudflare import paths** — never run the rename on it.
The jpillora namespace lives only on `embed` and is re-derived mechanically, so `embed` is
*regenerated* from `master` rather than merged (this keeps the ~182-file rename from ever producing
merge conflicts):

```bash
git fetch upstream
git checkout master && git merge upstream/master     # keep master == upstream (cloudflare paths)

# Rebuild embed = master + the 2-file embed patch + the mechanical rename:
git checkout embed
git reset --hard master
git cherry-pick <embed-patch commit(s)>              # embed.go + ingress/memory_origin.go (new); cmd.go, observer.go, ingress/origin_service.go, orchestration/{config,orchestrator}.go (edited)
bash scripts/rename-fork.sh                           # re-apply the jpillora namespace
git commit -am "jpillora namespace (scripts/rename-fork.sh)"
git push --force-with-lease origin embed             # history is regenerated each sync
```

`cmd/cloudflared/tunnel/cmd.go`, `connection/observer.go`, `ingress/origin_service.go`, and
`orchestration/{config,orchestrator}.go` are the files that can conflict (during the cherry-pick):
`cmd.go` around the guarded blocks (`sentry.Init`, `waitForSignal`, `notifySystemd`, the autoupdater
goroutine, the `observer := connection.NewObserver(...)` line, the `emb.onConfig` orchestrator hook,
and the `orchestratorConfig.IgnoreRemoteConfig` set), `observer.go` around `dispatchEvents` (the
sink-drain-before-event fix), `origin_service.go` around `newHTTPTransport`'s `unixSocketPath`
case (the in-memory-origin dial), `config.go` around the `Config.IgnoreRemoteConfig` field, and
`orchestrator.go` around the `ignoreRemote` field + the `UpdateConfig` gate. `embed.go` and
`ingress/memory_origin.go` are purely additive. If upstream renames `StartServer`, `tunnelFlags`,
`buildRunCommand`, `ParseToken`, `Init`, or the `connection.Observer` sink API, update `embed.go` to
match. Also re-copy the four dependency `replace` directives (see "Consuming this fork") if upstream
changes them.

## Caveats

- **quick tunnels** (`trycloudflare.com`) have no uptime guarantee and rotate their hostname each
  run — fine for dev/experimentation, not production. Named tunnels (token) give a stable
  hostname.
- **prometheus:** embedded tunnels do **not** touch the host's default prometheus registry.
  `makeMultiInstanceSafe` (first `Run`/`Listen` call) redirects
  `prometheus.DefaultRegisterer`/`DefaultGatherer` to a private, duplicate-tolerant registry, so
  cloudflared's per-tunnel registrations neither collide nor appear automatically. Note the flip
  side: after the first embedded tunnel starts, a host that *itself* uses the global
  `prometheus.DefaultRegisterer`/`promhttp.Handler()` sees that private registry, not the original
  default — hosts that want their own metrics should use an explicit `*prometheus.Registry`. The
  opt-in metrics server (`MetricsAddr`) serves cloudflared's metrics from the private registry.
- A harmless `failed to sufficiently increase receive buffer size` warning from quic-go may print
  on start; see the [quic-go UDP buffer sizes wiki](https://github.com/quic-go/quic-go/wiki/UDP-Buffer-Sizes).
